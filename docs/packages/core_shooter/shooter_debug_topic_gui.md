# shooter_debug_topic_gui

## Purpose

シューターシステムは操縦入力・ビジョン・ハードウェアの複数系統が揃わないと動作確認ができません。このTkinterベースのGUIツールは、実機やハードウェアがなくても各トピックを手動でパブリッシュ・モニタリングできるようにし、単体でのデバッグを可能にします。

## Inner-workings / Algorithms

Tkinterのウィジェットを各トピックのパブリッシャ／サブスクライバに結び付けた単一プロセスのGUIです。ROS2ノードとして動作し、ボタン操作がそのままトピック発行に対応します。

ターゲット指定は640x360のキャンバスを画像平面に見立て、クリック位置を `target_image_position` として発行します。これにより、カメラとビジョンパイプラインなしで [aim_bot](aim_bot.md) の自動追尾を試せます。

### 主な機能

**トピックパブリッシュ:**

- テストモード・手動モードの切替（`/test_mode`, `/manual_mode`）
- 射撃コマンド送信（単発・バースト・フルオート、左右独立）
- ヨー・ピッチ角の手動入力（`/left/test_yaw_angle` 等）
- シューターモーター速度の制御
- リロード・ディスクホールド操作
- 緊急停止の発行
- CANフレームの直接送信（`/can/tx`）

**モニタリング:**

- 残弾数（`/left/remaining_disk`, `/right/remaining_disk`）
- 射撃ステータス・コマンド値
- 距離センサ値
- 全17モーターの関節角度・速度（`/joint_states`）
- CAN送信フレームのリアルタイム表示

**ターゲット指定:**

- 640x360のキャンバス上でクリックしてターゲット画像位置を設定（`/left/target_image_position`, `/right/target_image_position`）

### テストモード

`/test_mode` を `true` にすると、[shooter_controller](shooter_controller.md) と [aim_bot](aim_bot.md) がテストモードに切り替わります。テストモードではジャム検出やシューターモーター回転コマンドの遅延チェックなど、一部の安全チェックがバイパスされます。

## Inputs / Outputs

購読・発行するトピックは上記「主な機能」の各項目に対応します。デバッグ用途のため、シューターパッケージの各ノードが扱うほぼ全てのトピックに接続します。

## Parameters

パラメータはありません。すべてGUI上の操作で設定します。

## Assumptions / Known limits

- デバッグ専用ツールです。試合運用のランチには含めないでください。
- テストモードでは安全チェックがバイパスされるため、実機に接続した状態で使用すると機構を破損させる可能性があります。
- Tkinterが利用可能なGUI環境が必要です。ヘッドレス環境（SSH接続のみ、X転送なし）では起動できません。

## 起動

```bash
ros2 run core_shooter shooter_debug_topic_gui
```
